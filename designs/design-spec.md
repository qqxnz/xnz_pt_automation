# 设计规范

## 1. 适用范围

本规范用于 PT 自动化系统的前端页面设计和设计稿产出，覆盖登录页、Dashboard、站点、种子、下载器、代理管理、任务和系统设置等页面。

## 2. 技术和组件基准

- 前端技术栈：`Vue 3 + Vite + TypeScript + Varlet UI`
- 页面需要兼顾桌面、平板和手机访问
- 优先使用 Varlet UI 组件，不额外引入复杂设计系统
- 页面结构以管理后台的清晰度和可操作性为优先

## 3. 视觉基准

```text
主色             #3f7cff
成功             #10b981
警告             #f59e0b
错误             #ef4444
页面背景         #f6f8fb
卡片背景         #ffffff
主文本           #111827
次级文本         #6b7280
边框             #e5e7eb
```

状态颜色：

```text
ONLINE       绿色
OFFLINE      红色
AUTH_FAILED  橙色
UNKNOWN      灰色
```

## 4. 响应式规则

```text
mobile   < 768px
tablet   768px - 1199px
desktop  >= 1200px
```

- 桌面端优先使用侧边栏、统计卡片和表格
- 平板端保留核心导航，减少表格字段
- 移动端优先使用顶部栏、卡片列表和底部/弹层操作

## 5. 设计稿产出规则

- 后续新增或调整设计稿时，仅输出 `.svg` 文件
- 不再额外生成 PNG、JPG 或其他扁平化预览文件
- SVG 文件直接放在 `designs/` 目录下
- 文件名使用页面或模块英文名，例如 `login.svg`、`dashboard.svg`、`sites.svg`
- 如果设计稿包含多个状态，可以使用 `模块-状态.svg`，例如 `sites-empty.svg`、`sites-auth-failed.svg`

已有的 `.svg.png` 文件属于历史产物，不作为后续设计稿交付格式。

## 6. 设计稿内容要求

- 标明页面主标题和关键操作入口
- 展示主要状态和异常状态
- 包含桌面端布局；涉及核心操作的页面需要补充移动端布局
- 敏感信息默认脱敏，例如 Cookie、密钥、密码和下载链接
- 按钮数量保持克制，优先突出主操作
- 站点表单中的 User-Agent 默认展示当前浏览器 User-Agent，并提供恢复当前浏览器 User-Agent 的操作
- 站点表单中的代理配置默认展示“不使用代理”；需要代理时从代理管理模块的已启用代理列表中选择，不设计全局默认代理入口

## 7. 模块方案&执行清单规范

每个模块的方案文档必须达到 AI 读取后即可完成该模块所有功能开发的粒度，不能只写概要。

开发前限制规则：

- 每个功能模块开发前，必须先检查 `README.md` 的【当前进度】表
- 必须确认该模块【设计稿】和【方案&执行清单】均为 `✅ 已完成`
- 如果设计稿未完成，必须提示缺少对应 `designs/*.svg` 文件，并先补齐设计稿
- 如果方案&执行清单未完成，必须提示缺少对应 `docs/*-plan.md` 或清单内容，并先补齐方案文档
- 任意一项未完成时，不进入该模块功能开发；补齐并更新进度表后再继续

模块方案必须包含：

- 模块目标和业务边界
- 页面路径、入口和跳转关系
- 页面布局、响应式规则和对应设计稿文件
- 功能列表和交互流程
- 表单字段、列表字段、筛选项和校验规则
- 接口路径、请求参数、响应结构和错误处理
- 前端状态管理、loading、空状态和异常状态
- 后端处理规则、数据持久化规则和安全要求
- 敏感字段脱敏、加密、日志规避规则
- 执行清单，按可开发任务拆分
- TODO，列出开发前仍需确认的问题
- 验收标准，覆盖桌面端、移动端、正常流程和异常流程

执行清单要求：

- 每一项必须是可落地的开发任务
- 不使用“完善页面”“处理逻辑”等过于笼统的描述
- 前端、后端、接口、状态、异常、验收相关任务需要分开写
- 涉及新增、编辑、删除、测试、同步等操作时，需要分别列出
- 如果模块依赖其他模块或接口，需要在 TODO 中明确标记
